# 后台编辑商品

后台「库存与运费」里，每个商品有两个按钮：

- **编辑商品**：名称、价格、单果约重、每箱个数、一句话卖点、商品介绍、商品图。
- **调整库存**：库存、上下架、下一批日期（原有功能）。

## 保存后哪里会变

| 位置                                                                       | 何时更新                         |
| -------------------------------------------------------------------------- | -------------------------------- |
| 下单页、认领页、手机版首页（价格、名称、规格、图片）                       | 立即                             |
| 桌面首页商品卡、商品详情页、购买指南（价格、名称、规格、卖点、介绍、图片） | 立即                             |
| 付款金额                                                                   | 立即，以 D1 为准，服务端重新计算 |
| 常见问题里的规格文字、网页标题、搜索引擎结构化数据（JSON-LD）、llms.txt    | 下次部署                         |
| 已创建订单（含待付款）                                                     | 不变，保留下单时金额             |

## 规则

- 改价格必须填写原因，保存前浏览器会再确认一次新旧价格。
- 每次保存在 `product_changes` 记录改动前后的值、操作人和原因，同时写审计日志。
- 两人同时编辑时，后保存的人会提示「商品信息已被其他人修改」，刷新后重填。
- 改价格会让正在打开的「调整库存」表单失效，需要刷新再改库存。
- 平安树 / 富贵树的箱数和每箱斤数由认领规则固定，只能改名称、价格、单果约重和文案。
- 商品名称修改后，后台历史订单列表里显示的也是新名称（订单里只存商品编号）。
- 商品图只接受后台上传的 JPG / PNG / WebP；勾选「恢复默认商品图」回到内置图片。

## 何时生效

页面每次打开都由 Worker 按数据库里的最新商品生成（每台服务器缓存约 10 秒），所以保存后首页、商品页、指南、下单页、网页标题和搜索引擎信息都会更新，不需要部署。

`src/lib/catalog-snapshot.json` 只是浏览器在读到数据前的兜底值。想让它与线上一致，可运行 `npm run catalog:pull`（只读查询线上数据库），非必需。
