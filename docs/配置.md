# 配置参考

## 配置分三层

`config/site.json` 是可以公开的站点配置，构建时同时供前台和 Worker 使用。改完运行 `npm run config:sync`，再重新构建。

`wrangler.jsonc` 保存云资源绑定和公开运行开关。所有正式环境设置写在 `env.production`；Wrangler 的环境绑定不自动继承顶层配置。顶层配置只用于本地。

`.dev.vars` 仅供本地；正式秘密使用 Worker Secrets。不要把秘密放在 JSON 站点配置或 `PUBLIC_*` 环境变量中。

## 通用商品目录

通过 `npm run products` 新增、编辑和移除商品，或修改 `config/products.json` 数组。可配置 1–200 个商品，SKU 和网页 slug 各自唯一。

| 商品字段            | 说明                                                                                        |
| ------------------- | ------------------------------------------------------------------------------------------- |
| `sku`               | 大写字母、数字、下划线或连字符，最多 40 位；如 `BOOK_001`、`TSHIRT_M`。已售商品保持编号不变 |
| `slug`              | 商品页路径，只用小写英文、数字和连字符                                                      |
| `name` / `category` | 商品名称与分类                                                                              |
| `unit`              | 销售单位，例如本、件、盒、包、只                                                            |
| `price`             | 人民币整数分，最低 300 分                                                                   |
| `specification`     | 自由规格，例如 M 码 / 黑色、500 克、350mL                                                   |
| `description`       | 真实商品介绍，不使用 HTML                                                                   |
| `image`             | `/images/...` 图片路径或 HTTPS 图片地址                                                     |
| `active`            | 是否上架，true / false                                                                      |
| `maxPerOrder`       | 每单限购，1–20 个购买单位                                                                   |

不同尺码或颜色分别配置 SKU；目前每次订单购买一种规格。商品规格不要求水果重量或每箱个数。国内实物配送以当前地址结构为基础；数字商品自动交付和多币种需额外开发。

## 站点字段

| 字段                                          | 用途                                                            |
| --------------------------------------------- | --------------------------------------------------------------- |
| `name` / `publisher`                          | 使用者自己的商店名称和经营者                                    |
| `url`                                         | 正式 HTTPS 源地址，无尾斜杠                                     |
| `originLabel`                                 | 公开发货地，只填允许公开的城市或区域                            |
| `ownerWechat` / `wechatQrUrl`                 | 客服微信与可选二维码                                            |
| `ownerXUrl` / `twitterHandle`                 | 商店自己的可选主页信息，与开源作者署名分开                      |
| `storefront.headline` / `.description`        | 首页主标题与介绍                                                |
| `storefront.shippingNote` / `.afterSalesNote` | 真实配送和售后规则，商品、订单和指南共用                        |
| `storefront.seasonal`                         | 是否限时销售，默认 false；true 时按 season 日期限制新下单       |
| `season.start` / `.end` / `.label`            | 销售期与原果园模块预约截止日、标签                              |
| `features.orchard`                            | 原果园主题、认领和活动扩展示例，默认 false                      |
| `paymentProject`                              | 同一 Stripe 商户账号内的本站唯一标识；有真实订单后保持不变      |
| `shipping.remoteProvinces` / `.remoteFee`     | 需补差价的省份代码和每购买单位的运费，金额为整数分              |
| `mapOrigin.code` / `.name`                    | 配送地图的发货城市                                              |
| `contentUpdated`                              | 内容更新时间 YYYY-MM-DD                                         |
| `prices`                                      | 仅供原果园模块四个保留 SKU 使用；通用商品价格写在 products.json |

开源作者信息定义在 `src/lib/credits.ts`，默认页脚显示“得否科技 · 得否开源”和 [X @wangdefou](https://x.com/wangdefou)。此信息说明代码来源，与使用者自己的经营者信息分开。

## 将目录修改应用到已有商店

1. 修改商品或站点配置，运行 `npm run config:sync`。
2. 检查生成的 `scripts/catalog-update.sql`。
3. 本地：`npx wrangler d1 execute DB --local --file scripts/catalog-update.sql`。
4. 正式：先备份，再执行 `npx wrangler d1 execute DB --remote --env production --file scripts/catalog-update.sql`。
5. 在后台设置新增商品的真实库存，重新构建并部署。

更新 SQL 新增商品时库存为 0，更新名称、价格、规格、单位和上架开关；移除的商品下架保留。它不清空订单、不改库存，也不改已付金额或既有认领权益。历史订单仍引用原 SKU，不应把已售 SKU 改成完全无关的商品；换商品请新增 SKU，并下架旧商品。

`seed.sql` 仅初始化缺失记录，已有安装应使用 catalog-update。重复运行本地 `setup` 会同步目录并把上架商品的演示库存恢复到 100。`demo-stock.sql` 只用于本地，不能用于正式库存。

## 原果园模块

启用 `features.orchard` 后，四个保留编号 FAMILY / GIFT / PA / FG 生效。平安树与富贵树权益仍为 8 / 15 箱，tier=888/1888 是类型标识；修改权益数量需要新增数据库迁移与同步履约逻辑。关闭展示不抹掉历史认领和已付款订单。

## 公开开关与 Secret

| 公开运行值（`env.production.vars`）                     | 说明                                                                         |
| ------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `APP_ORIGIN`                                            | 由 config:sync 同步，必须与 `site.url` 一致                                  |
| `SALES_OPEN`                                            | 初始 false，开售前完成支付回调和库存验证                                     |
| `SITE_OFFLINE`                                          | false；设 true 会拦截包括 Webhook 在内的所有请求，先停止新支付并处理在途回调 |
| `DEMO_MODE` / `SANDBOX_CHECKOUT`                        | 正式环境都必须 false                                                         |
| `STRIPE_MODE`                                           | 正式 live；隔离测试环境 sandbox                                              |
| `STRIPE_PAYMENT_METHOD_CONFIGURATION`                   | 可选，自己 Stripe 账号的支付方式配置 ID                                      |
| `ACCESS_TEAM_DOMAIN` / `ACCESS_AUD`                     | 自己 Access 团队域与应用 Audience                                            |
| `TURNSTILE_SITE_KEY`                                    | 正式域名的人机验证公开 key                                                   |
| `MEDIA_BASE_URL`                                        | 保持空字符串，图片和发票由本站 `/media/` 路由处理                            |
| `OFFICIAL_QR_URL` / `HERO_VIDEO_URL`                    | 可选的公开公众号二维码和视频                                                 |
| `NOTIFICATIONS_ENABLED`                                 | 可选通知，默认 false                                                         |
| `NOTIFICATION_START_DATE`                               | 通知统计起点，默认销售开始日                                                 |
| `NOTIFICATION_DAILY_HOUR` / `NOTIFICATION_DAILY_MINUTE` | 北京时间日报发送时间，默认 00:05                                             |
| `TRACKING_ENABLED`                                      | 可选快递100轨迹，默认 false                                                  |
| `GOOGLE_ANALYTICS_ID` / `CLOUDFLARE_ANALYTICS_TOKEN`    | 可选访客统计标识，初始为空                                                   |

| Secret                                                | 何时需要                                            |
| ----------------------------------------------------- | --------------------------------------------------- |
| `ADMIN_EMAIL`                                         | 公网后台必须，与 Access 允许邮箱完全一致            |
| `TURNSTILE_SECRET_KEY`                                | 公网提交表单必须                                    |
| `STRIPE_SECRET_KEY`                                   | 真实支付必须；建议受限 key，使用正确 live/test 环境 |
| `STRIPE_WEBHOOK_SECRET`                               | 支付必须，对应本站 Webhook 的签名 Secret            |
| `STRIPE_REFUND_SECRET_KEY`                            | 启用后台真实退款时需要，独立最小权限 key            |
| `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID`             | 开启经营通知时需要                                  |
| `KUAIDI100_CUSTOMER` / `KUAIDI100_KEY`                | 开启实时轨迹时需要                                  |
| `GOOGLE_SITE_VERIFICATION` / `BING_SITE_VERIFICATION` | 可选站点验证                                        |

开启通知后会向配置的 Telegram 目标发送经营信息，请先用自己的私聊做连接测试。不要填群聊或原项目的凭证。日志和通知不包含买家姓名、手机号、地址、PIN 或完整券码。

## 图片与页面文案

通用商品图片放在 `public/images/`，通过 products.json 的 image 引用；自带 SVG 演示图可替换成自己的授权图片。默认图与二维码均不依赖原站图床。

通用首页和订单服务文案改 site.json 的 storefront。更深的页面修改位于 `StoreHome.astro`、`StoreShop.tsx`、`StoreGuide.astro` 和 `StoreLayout.astro`。原果园示例的多尺寸图片仍通过 `src/lib/image-assets.json` 管理。
