# 部署指南

从零把商店部署到自己的域名。需要：

- 一个 Cloudflare 账号，域名已经托管在 Cloudflare
- 一个 Stripe 账号（先用测试模式）
- 本机安装 Node.js 24

下面的命令都在项目目录里运行。

## 1. 登录 Cloudflare

```bash
npm install
npx wrangler login
```

## 2. 创建数据库、缓存和图片存储

```bash
npx wrangler d1 create defou-shop
npx wrangler kv namespace create CACHE
npx wrangler r2 bucket create defou-shop-media
```

把前两条命令输出的 `database_id` 和 `id` 填进 `wrangler.jsonc` 的 `env.production` 里对应的 `<…>` 位置，同时填好：

- `routes`：你的域名和它所在的 Cloudflare 区域
- `APP_ORIGIN`：`https://你的域名`

再把 `config/store.json` 里的 `brand.siteUrl` 改成同一个网址。

## 3. 初始化数据库

```bash
npx wrangler d1 migrations apply DB --env production --remote
npx wrangler d1 execute DB --env production --remote --file scripts/seed.sql
npx wrangler d1 execute DB --env production --remote --file scripts/seed-content.sql
npx wrangler d1 execute DB --env production --remote --file scripts/regions.sql
```

商品初始库存为 0、示例价格来自苹果店，上线后在经营后台修改。

## 4. 配置后台登录（Cloudflare Access）

经营后台和网站设置都用 Cloudflare Access 登录保护（免费额度够用）。

1. Cloudflare 后台 → Zero Trust → Settings 里记下团队域名（形如 `xxx.cloudflareaccess.com`）。
2. Zero Trust → Access → Applications → Add an application → Self-hosted。
3. 添加两条路径：`你的域名/admin*` 和 `你的域名/api/admin/*`。网站设置在 `/admin/studio`，也被这两条覆盖。
4. 策略选 Allow，Include 里填允许登录的邮箱。
5. 保存后在应用详情里复制 Application Audience (AUD) Tag。

把团队域名和 AUD 填进 `wrangler.jsonc` 的 `ACCESS_TEAM_DOMAIN`、`ACCESS_AUD`，然后设置管理员名单：

```bash
npx wrangler secret put ADMIN_EMAIL --env production    # 经营后台，多个邮箱用逗号分隔
npx wrangler secret put STUDIO_EMAIL --env production   # 网站设置，通常只填店主
```

## 5. 人机验证（Turnstile）

Cloudflare 后台 → Turnstile → Add widget，域名填你的域名。站点密钥填进 `wrangler.jsonc` 的 `TURNSTILE_SITE_KEY`，服务端密钥：

```bash
npx wrangler secret put TURNSTILE_SECRET_KEY --env production
```

## 6. 接入 Stripe

1. Stripe 后台（先在测试模式）→ 开发者 → API 密钥 → 创建受限密钥，Checkout Sessions 给写权限。
2. 开发者 → Webhooks → 添加端点：`https://你的域名/api/stripe/webhook`，订阅事件：
   `checkout.session.completed`、`checkout.session.async_payment_succeeded`、`checkout.session.async_payment_failed`、`checkout.session.expired`、`charge.refunded`、`refund.created`、`refund.updated`、`refund.failed`。
3. 写入密钥：

```bash
npx wrangler secret put STRIPE_SECRET_KEY --env production
npx wrangler secret put STRIPE_WEBHOOK_SECRET --env production
# 可选：后台一键退款，另建一个只有 Refunds 写权限的受限密钥
npx wrangler secret put STRIPE_REFUND_SECRET_KEY --env production
```

`STRIPE_MODE` 保持 `sandbox` 直到测试付款、退款都跑通，再换成正式密钥并改为 `live`。

同一个 Stripe 账号还服务其他网站时，修改 `src/lib/payment-project.ts` 里的项目名，避免互相处理对方的付款。

## 7. 部署

```bash
npm run deploy
```

部署后：

1. 打开 `https://你的域名/admin/studio`，在「网站内容」里换成自己的店名、文案和配图。
2. 打开 `https://你的域名/admin` →「商品」改名称和价格，→「库存与运费」填库存并上架。
3. 准备开卖时，把 `wrangler.jsonc` 里的 `SALES_OPEN` 改为 `true` 并重新部署；日常暂停接单在「网站设置 → 接单与运费」。
4. 检查公开页面：`npm run verify:pages -- https://你的域名 --production`。

## 可选服务

**Telegram 订单通知**：创建机器人后写入 `TELEGRAM_BOT_TOKEN`、`TELEGRAM_CHAT_ID` 两个密钥，把 `NOTIFICATIONS_ENABLED` 改为 `true`。日报时间在「网站设置 → 网站内容 → 通知」。

**快递 100 物流查询**：写入 `KUAIDI100_CUSTOMER`、`KUAIDI100_KEY`，把 `TRACKING_ENABLED` 改为 `true`。查询时会把快递公司、运单号以及部分快递公司要求的收件电话发给快递 100，请在隐私说明里告知顾客。

**访问统计与搜索验证**：在「网站设置 → 网站内容 → 搜索与统计」里填写。

## 日常维护

- 数据库结构变化写成新的 `migrations/00xx_*.sql`，不要修改已经应用过的迁移；部署前先运行 `npx wrangler d1 migrations apply DB --env production --remote`。
- D1 自带 30 天时间回溯，出问题可用 `npx wrangler d1 time-travel restore` 恢复到某个时间点。
- 「网站设置 → 域名与站点 → 全部部署设置」列出每一项部署设置是否已配置。
