# 换成你自己的店

这个项目的版式来自正在运营的「太行深处」苹果商店（apple.defou.ai）：首屏大图、四个承诺、产地故事、一年的工序、商品卡、配送足迹、日记和常见问题。卖茶叶、蜂蜜、核桃或手作，都可以沿用这套版式，只换文字、图片和商品。

改动按难度分三层，大部分店铺只需要前两层。

## 一、改一个配置文件：`config/store.json`

页面上的文字、开关和图片都在这个文件里。

| 段落       | 管什么                                                                                        |
| ---------- | --------------------------------------------------------------------------------------------- |
| `brand`    | 店名、经营者、正式网址、产地、口号、页脚文字、主题色、Logo、微信和 X 联系方式                 |
| `season`   | 销售季开始与结束日期、顶部横条文字                                                            |
| `features` | 四个可选模块的开关，见下文                                                                    |
| `words`    | 常用词：商品叫什么（苹果 / 茶）、包装单位（箱 / 罐）、数量单位（个 / 包）、规格标签、导航文字 |
| `home`     | 首页每一屏的文字：首屏、四个承诺、故事、工序、商品区、更多玩法、足迹、日记、常见问题          |
| `pages`    | 下单页、订单页、商品详情页、购买指南的标题和说明                                              |
| `faqs`     | 常见问题列表，首页用 `home.faq.pick` 挑其中几条（从 0 开始数）                                |
| `seo`      | 每个页面的网页标题、描述和关键词，以及给搜索引擎、AI 搜索看的品牌信息                         |
| `images`   | 换图，见下文                                                                                  |

上线后，这些内容都可以在网站设置（`/admin/studio`）里用表单修改，保存即生效，不需要改这个文件；`config/store.json` 只是新店的初始内容。文件里网页标题模板（`seo.product`）等少数技术项可以用 `{brand}`、`{origin}`、`{name}` 等占位符，系统自动替换，这些项不出现在网站设置界面里。

改完先检查格式，它会逐条指出缺了哪项、类型写错或图片找不到：

```bash
npm run config:check
```

### 四个可选模块

| 开关           | 模块                                   | 关掉后                                                                                                       |
| -------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `adoption`     | 认领果树：铭牌、PIN 登录、分次预约发货 | `/tree`、`/tree/my` 不存在，认领接口返回 404，导航、首页、页脚、后台「认领」标签都隐藏，下单接口拒绝认领订单 |
| `sponsorship`  | 活动赞助：申请、审核、返图墙           | `/treat` 不存在，申请接口返回 404，后台「活动审核」隐藏                                                      |
| `footprintMap` | 配送足迹地图：城市级汇总               | `/map` 不存在，首页「在路上」一屏和足迹接口关闭                                                              |
| `diary`        | 日记：后台发图文，首页展示             | 首页日记一屏和接口关闭，后台「采摘日记」隐藏                                                                 |

关掉的模块数据库表仍然保留，以后打开即可使用。

### 换图

`images` 里每一项写 `null` 表示用内置图片，换成自己的照片：

1. 把照片放到 `public/images/` 下，例如 `public/images/my-shop/hero.jpg`。
2. 写上路径和原图尺寸：

```json
"hero": { "src": "/images/my-shop/hero.jpg", "width": 1600, "height": 1000, "alt": "茶园清晨" }
```

| 键               | 用在                                     |
| ---------------- | ---------------------------------------- |
| `hero`           | 首页首屏大图、故事配图                   |
| `FAMILY`、`GIFT` | 两个商品的默认图（后台上传的商品图优先） |
| `PA`、`FG`       | 认领模块的两档商品图                     |
| `community`      | 活动赞助卡片图                           |

Logo 写在 `brand.logo`，格式相同。建议照片宽 1600px 左右，存成 JPG 或 WebP，单张不超过 500KB。

## 二、商品：在后台改

上线后打开 `/admin` →「商品」→「编辑」：名称、价格、规格、卖点、介绍、商品图都在这里，保存后前台立即更新，不用重新部署。详见 `docs/后台编辑商品.md`。

商店固定两个零售商品位（编号 `FAMILY` 和 `GIFT`，一个日常、一个送礼），开启认领模块时另有两档认领（`PA`、`FG`）。

## 三、预览和上线

```bash
npm run config:check
npm run build && npm run preview   # 本地预览（需先按 README 初始化本地数据库）
npm run deploy                     # 构建并部署，构建前会先检查配置
```

想先看看换成别的店是什么样，可以用自带的茶叶示例（关闭了认领、赞助和地图，图片是占位图）：

```bash
STORE_CONFIG=config/examples/tea.json npm run build && npm run preview
```

## 还需要直接改代码的地方

- **购买指南、隐私说明的正文**：在 `src/pages/guide.astro` 和 `src/pages/privacy.astro`。长篇说明直接改页面文件更方便，店名和经营者已经自动替换。
- **认领、赞助、足迹地图模块内部的文字**：在 `src/components/Treat.tsx`、`MyTree.tsx`、`MapPage.tsx`，目前按苹果园写成，开启这些模块时需要改（地图的出发城市和简介在网站设置里改）。
- **配色和字体**：`src/styles/global.css`。
- **商品固定为两个零售位**：增加第三个商品需要改下单校验和页面，暂不支持配置。
