# 架构与安全

## 请求与存储

`src/worker.ts` 是自定义 Worker 入口，先检查维护开关，再分流静态资源、静态公开页、`/api/*`、私有媒体与 Astro 动态页。公开页面预生成；订单、支付结果、后台、我的果树保持动态且不缓存。`npm run dev:pages`（astro dev）不执行自定义 Worker 分流，完整体验使用构建后的 `astro preview`。

- D1：商品、事务库存、订单、认领、预约、优惠券、审核、审计及通知队列。
- KV：城市级汇总等可重建缓存，不保存支付真相。
- R2：上传图片与私有发票，必须保持桶私有。
- ASSETS：随构建发布的公开文件，无需原站图床。

`migrations/` 是完整结构历史。第 0016 号迁移将认领类型从按金额判断改为按订单 SKU 判断，截止日从配置快照读取，允许修改售价而不改变认领档位。

## 保留的业务保护

- 公网后台同时通过 Access JWT 和管理员邮箱；不信任单独的邮箱请求头。
- DEMO_MODE 的权限只对回环地址生效，不能公开演示后台。
- 服务端计算价格与运费；支付回调核对签名、项目归属、环境、CNY 和金额。
- 创建支付前保存不可变参数、请求幂等键、库存/券占用；未知结果保持锁，避免重复扣款或错误释放。
- 退款单独持久化请求、核对原付款和剩余金额；最终结果仍由签名回调确认。
- 认领 PIN 加盐哈希；重置撤销旧会话并记录审计。
- 联系资料默认脱敏，按需查看留审计；地图仅公开城市汇总。
- 券明文由浏览器生成并下载，数据库保存哈希与标记，不写日志、通知或统计。
- 上传图片经过客户端缩放和 Worker 元数据清理。经营者仍应检查人脸、门牌、面单等画面内容。

## 开源导出边界

本仓库从明确的代码、迁移、合成测试和公共字典文件导出，创建全新 Git 历史。未复制旧 `.git`、运行时环境、部署输出、生产标识、私人二维码、品牌图像、客户表格、订单或真实券清单。示例数据使用虚构联系人。

`npm run scan:public` 是仓库内置规则检查，不是对所有未知秘密格式的证明。对自己的衍生仓库仍应在发布前检查新增文件、启用 GitHub Secret Scanning，并保持 `.gitignore`。

## 自检边界

类型检查、业务测试、构建检查和本地完整预览验证代码与默认体验；它们不证明使用者的 Stripe 账号资质、真实设备支付、Access 策略或物流账户已配置正确。生产 doctor 检查格式和必需 Secret 的名字，不读取密钥值，也不能替代上述服务的实际验收。

## 维护

升级依赖后运行所有 CI 检查。修改数据库使用新增 migration；修改静态价格同时更新数据库和重新构建。不可在已接收真实订单后随意更改 `paymentProject` 或清空数据库。先备份再进行结构迁移，私有备份不要提交。
