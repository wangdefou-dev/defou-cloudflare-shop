# 部署自己的 Cloudflare 通用商店

## 1. 本地体验与账号

先完成 README 的 `npm ci`、`npm run setup` 和完整本地预览。正式部署需要自己的 Cloudflare 账号及可用域名；真实收款需要自己的 Stripe 商户账号。R2 可能需要先在账号内启用。费用与资格以各服务控制台为准。

```bash
npx wrangler login
npx wrangler d1 create my-orchard
npx wrangler kv namespace create CACHE
npx wrangler r2 bucket create my-orchard-media
```

从命令结果获得 D1 `database_id`、KV `id`。保持 R2 私有，不启用 r2.dev 公共桶或公开自定义域名；该桶还会保存私有发票。

## 2. 公开配置

```bash
npm run configure
npm run config:check
```

向导写入 `config/site.json` 和 `wrangler.jsonc` 的 `env.production`。填自己的站点域名、Worker 名、资源 ID、Access 和 Turnstile 公开值。也可以手工填写，之后运行 `npm run config:sync`。

在 `env.production.routes` 添加自己的自定义域名（将此示例替换为真实域名）：

```json
"routes": [{ "pattern": "shop.your-domain.com", "custom_domain": true }]
```

域名位于自己的 Cloudflare zone。可保留 `workers_dev=true` 用于排查；正式后台始终独立验证 Access JWT，即使直接访问 Worker 子域也不会绕过。

正式开关保持 `DEMO_MODE=false`、`SANDBOX_CHECKOUT=false`、`SALES_OPEN=false`、`SITE_OFFLINE=false`。`APP_ORIGIN` 必须与 `config/site.json.url`、Access 域名和 Stripe 回跳域名一致。

## 3. 初始化远端数据库

```bash
npm run db:migrate:production
npm run db:seed:production
npm run db:regions:production
```

这三条命令分别应用迁移、写入零库存商品目录和运费设置、导入公开行政区划。正式种子不包含客户、订单、优惠码、历史销量或演示库存。

## 4. Access 与 Turnstile

在 Cloudflare Zero Trust 创建 Access self-hosted 应用，保护本站 `/admin`、`/admin/*`、`/api/admin/*`；为私有发票路径 `/media/apple-2026/*.pdf` 配置相同保护。只允许自己的管理员邮箱。使用能给浏览器签发 JWT 的登录方式，不使用绕过策略。

填写 Access team domain（如 `your-team.cloudflareaccess.com`）和应用 Audience 到公开 vars；管理员邮箱保存为 `ADMIN_EMAIL` Secret。Worker 验证 issuer、audience、RS256 签名、有效期与邮箱。

不要用 Access 保护整个域名，否则 Stripe Webhook 和公开页面会被拦截。商品图片和公开 `/api/config` 不需管理员认证。

在 Turnstile 控制台创建正式站点并允许自己的域名，公开 site key 写入 vars，secret key 只放 Secrets。正式环境不可使用测试人机验证 key。

## 5. Secrets 与首次发布

逐个安全输入（不会写入源码）：

```bash
npx wrangler secret put ADMIN_EMAIL --env production
npx wrangler secret put TURNSTILE_SECRET_KEY --env production
```

Wrangler 可能提示先创建 Worker；允许它创建**自己的新 Worker**。也可以在 Cloudflare 控制台创建同名空 Worker 后添加 Secrets。首次仅用于初始化时，可在保持 `SALES_OPEN=false` 且配置完成的条件下运行：

```bash
npm run build:production
npx wrangler deploy --env production
```

随后运行 `npm run doctor -- --production` 核对资源和 Secret 名单。后续部署使用 `npm run deploy`。

批量上传可从 `.secrets.production.example.json` 复制为 `.secrets.production.json`，只填写需要的字段，删除未使用的空字段，然后运行 `npm run secrets:production`。该文件被 Git 忽略，不要将其传入前端构建或提交。初始模板所有值为空，不能直接上传。

首次发布后确认：未登录的 `/admin` 和 `/api/admin/data` 被拒绝；允许邮箱可登录；直接打开发票链接需要授权。不要仅凭页面 200 就认定身份验证正常。

## 6. Stripe：先隔离测试，再正式开售

本地模拟支付不验证你的真实收款配置。新接入先使用独立 Stripe sandbox；为远程测试复制一套独立 Worker / D1 / KV / R2 与 Access 应用，不能复用生产数据库。复制 `env.production` 到 `env.sandbox`，换全部资源与域名，设置 `STRIPE_MODE=sandbox`、`SANDBOX_CHECKOUT=true`。使用 `CLOUDFLARE_ENV=sandbox npx astro build` 与 `npx wrangler deploy --env sandbox`；默认生产 doctor 不用于沙盒。

沙盒只接受 test key，测试人机验证也仅接受该隔离沙盒或本机。真实浏览器支付和验签 Webhook 都测试通过后，才回到 production 配置。

正式账号创建专用受限 key，至少按实际调用授予 Checkout Sessions 读写、PaymentIntents/Charges/Refunds 所需读取权限；后台退款用独立的具备退款写权限的受限 key。具体权限以 Stripe 返回的权限检查和账号控制台为准，不给无关业务授权。

```bash
npx wrangler secret put STRIPE_SECRET_KEY --env production
npx wrangler secret put STRIPE_WEBHOOK_SECRET --env production
# 可选：需要后台发起真实退款时
npx wrangler secret put STRIPE_REFUND_SECRET_KEY --env production
```

为本站创建 Webhook，地址：`https://你的域名/api/stripe/webhook`，API 版本 `2026-09-30.endive`。订阅：

- `checkout.session.completed`
- `checkout.session.async_payment_succeeded`
- `checkout.session.async_payment_failed`
- `checkout.session.expired`
- `charge.refunded`
- `refund.created`
- `refund.updated`
- `refund.failed`

把此端点的签名 Secret 填入 `STRIPE_WEBHOOK_SECRET`。回调不经过 Access 登录，Worker 独立验签；付款必须同时匹配项目 metadata、订单、环境、币种与金额。到账与履约由签名回调推进，返回成功页面不代表付款完成。

支付币种固定 CNY。手机默认偏向支付宝，也可选银行卡；可用方式由你的 Stripe 账号、地区和支付方式配置决定，不保证每个账号都有支付宝/微信支付。微信内置浏览器会引导系统浏览器付款。

## 7. 开售与可选服务

1. 替换演示图片，核实商品规格、发货地、售后承诺与隐私说明。
2. 如开启限时销售，填好真实销售日期；在后台设置真实库存，保留库存调整原因。
3. 将 `SALES_OPEN=true`，运行 `npm run deploy`。
4. 使用自己的测试流程核对下单、Webhook、订单和库存；不拿真实客户订单做退款或 PIN 重置验收。

Telegram、快递100与统计都是可选项，缺省关闭。填写自己的凭证后再打开相应开关，详见 [配置参考](配置.md)。定时任务每五分钟处理维护与通知重试；公开页不需要这些服务即可展示。
